## 1. Паспорт проекта

- **Название проекта:** `Семантический поиск для заметок`
- **Автор:** `<Есть в СДО>`
- **Группа:** `<Есть в СДО>`
- **Контакт:** [Telegram](https://t.me/TheHollowHorizon/)

- **Краткое описание:**
> Небольшой NLP проект: сервис семантического поиска и проверки релевантности по локальной базе заметок.
> Основной способ запуска - **Docker**. Так проект не зависит от локальной версии Python, Windows/Linux окружения и наличия готовых wheels для `numpy` / `scikit-learn`.

## 2. Структура проекта

Проект организован в следующей структуре:
- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов;
  - конфиги проекта.
- `data/` – демонстрационные/учебные данные:
  - небольшие заметки по которым ведётся поиск.
  - при необходимости – небольшие выборки для быстрого запуска.
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example` и т.п.
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.
- FastAPI эндпоинты `/health`, `/predict`, `/search`, `/reindex`;
- Dockerfile и docker-compose;

## 3. Требования и установка

Достаточно установить Docker / Docker Desktop, остальное будет установлено при развёртывании контейнера.

```bash
docker compose up --build
```

## 4. Как запустить проект

После запуска через Docker сервис будет доступен по адресу:

```text
http://localhost:8000
```

Проверка health-check:

```bash
curl http://localhost:8000/health
```

Пример запроса к `/predict`:

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"query":"Как сделать Dockerfile для FastAPI сервиса?","top_k":3}'
```

Остановка:

```bash
docker compose down
```

## Что происходит при сборке Docker-образа

На этапе `docker build` автоматически выполняются команды:

```bash
python -m src.data.prepare_dataset
python -m src.data.eda
python -m src.models.train
python -m src.models.evaluate
pytest -q
```

То есть после сборки образа внутри уже есть:

```text
artifacts/        обученный TF-IDF retrieval и LogisticRegression classifier
reports/          EDA и метрики
```

## Makefile-команды

Если установлен `make`, можно использовать короткие команды:

```bash
make docker-build      # собрать образ
make docker-run        # запустить контейнер
make docker-up         # docker compose up --build
make docker-down       # остановить docker compose
make docker-test       # запустить pytest внутри контейнера
make docker-evaluate   # пересчитать метрики внутри контейнера
```

## Локальный запуск без Docker

Локальный запуск оставлен только как dev-вариант. Рекомендуемый Python: 3.11 или 3.12.

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip setuptools wheel
pip install -r requirements.txt

python -m src.data.prepare_dataset
python -m src.data.eda
python -m src.models.train
python -m src.models.evaluate
uvicorn src.service.app:app --reload --host 0.0.0.0 --port 8000
```

Если локальная установка падает на `numpy` / `scikit-learn` / `ninja`, то опять-таки, проще запускать через Docker.

## API

### `GET /health`

Проверяет состояние сервиса и наличие обученных артефактов.

### `POST /predict`

Выполняет поиск релевантных фрагментов и предсказывает, достаточно ли найденного контекста для ответа.

Пример входа:

```json
{
  "query": "Как сделать Dockerfile для FastAPI сервиса?",
  "top_k": 3
}
```

Пример ответа:

```json
{
  "query": "Как сделать Dockerfile для FastAPI сервиса?",
  "answerable": true,
  "answerable_score": 0.91,
  "chunks": [
    {
      "note_id": "docker.md",
      "chunk_id": "docker.md::0",
      "text": "Dockerfile описывает окружение сервиса...",
      "score": 0.82,
      "relevance_score": 0.91
    }
  ]
}
```

### `POST /search`

Возвращает только найденные чанки без классификации answerability.

### `POST /reindex`

Пересобирает chunks и переобучает модели. В учебной версии endpoint полезен для демонстрации pipeline.

## 5. Данные

В проекте используется демонстрационная локальная база заметок в формате Markdown. Данные находятся в папке `data/notes/` и представляют собой небольшие учебные документы по темам FastAPI, Docker, RAG, метрик машинного обучения, EDA, логирования, TTS-пайплайнов и особенностей изоляции Kotlin-кода через ClassLoader.

Для обучения и оценки релевантности используется файл `data/qrels.csv`. В нём заданы пары пользовательских запросов и релевантных документов/чанков. Эти данные используются для проверки качества поиска, обучения классификатора релевантности и расчёта метрик.

В репозитории хранятся только небольшие демонстрационные данные, необходимые для быстрого запуска проекта. Конфиденциальные данные, личные заметки и большие корпуса документов в репозиторий не добавляются. При необходимости проект можно расширить, добавив новые `.md`-файлы в `data/notes/` и соответствующие пары запросов и релевантных документов в `data/qrels.csv`.

Подготовка данных выполняется командой:

```bash
python -m src.data.prepare_dataset
````

В результате создаются подготовленные чанки документов и артефакты, необходимые для дальнейшего обучения и поиска.

Дополнительно выполняется EDA:

```bash
python -m src.data.eda
```

Либо пересобрать Docker контейнер, тогда все заметки будут проиндексированы заново.

EDA позволяет оценить количество документов, количество чанков, длину текстовых фрагментов и общую структуру демонстрационного корпуса.

## 6. Тесты

В проекте добавлены базовые тесты для проверки работоспособности API-сервиса. Тесты находятся в папке `tests/`.

Проверяются следующие сценарии:

* сервис FastAPI успешно создаётся и импортируется;
* endpoint `/health` возвращает корректный статус;
* endpoint `/predict` принимает пользовательский запрос и возвращает ответ в ожидаемом формате;
* в ответе `/predict` присутствуют признаки работы модели: найденные чанки, score релевантности, флаг `answerable` и режим поиска.

Запуск тестов выполняется командой:

```bash
pytest tests
```

При запуске через Docker тесты выполняются автоматически на этапе сборки образа. Это позволяет убедиться, что сервис, подготовка данных, обучение модели и базовые API-сценарии воспроизводятся в контейнере.

## 8. Ограничения и дальнейшая работа

Текущая версия проекта является учебным прототипом и имеет ряд ограничений.

Основные ограничения:

* используется небольшой демонстрационный корпус заметок;
* разметка релевантности в `qrels.csv` ограничена небольшим числом запросов;
* качество классификатора релевантности зависит от объёма и качества разметки;
* генерация ответа реализована в упрощённом виде на основе найденных фрагментов;
* в базовой конфигурации используется TF-IDF-поиск, который хуже обрабатывает сложные семантические совпадения;
* отсутствует полноценная авторизация и разграничение доступа к заметкам;
* нет постоянного внешнего хранилища для пользовательских документов;
* не реализован веб-интерфейс для загрузки и просмотра заметок.

Возможные направления дальнейшего развития:

* расширить корпус заметок до 50–100 документов;
* добавить больше размеченных запросов для обучения и оценки;
* подключить embedding-модель, например multilingual SentenceTransformer;
* добавить reranker для более точной сортировки найденных чанков;
* реализовать генерацию ответа через локальную или внешнюю LLM;
* добавить endpoint для загрузки новых документов;
* добавить инкрементальное обновление индекса;
* добавить хранение индекса и метаданных в SQLite, ChromaDB или FAISS;
* реализовать авторизацию пользователей;
* добавить логирование пользовательских запросов и мониторинг качества ответов.

Таким образом, текущая версия закрывает базовый сценарий: загрузка документов, подготовка данных, построение индекса, обучение модели релевантности, оценка качества и запуск API-сервиса. Дальнейшее развитие может превратить прототип в полноценный сервис поиска и ответов по персональной базе знаний.
